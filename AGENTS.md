# AGENTS.md — go-meta working guide

Go + Fiber v3 + templ (SSR) + Svelte 5 (client-only) meta-framework.
Phase 1: file routing, rendering modes, layout ownership, soft navigation.

**Read `phase1-implementation-blueprint.md` for binding decisions before
changing anything architectural.** Its §0 rules are not negotiable
(client-only Svelte, Node at build time only, mode by exact filename,
browser-native semantics win, etc.).

## Commands

| Command | Purpose |
|---|---|
| `make generate` | templ + route codegen (always precedes go build) |
| `make build` | full production build (binary + Vite assets) |
| `make test` | vet, Go tests, svelte-check, tsc, vitest |
| `make e2e` | real-Chromium E2E against the built binary |
| `make verify` | **everything**: test + build + gofmt/diff hygiene + e2e |

Run `make verify` before claiming any task done. It is the complete gate
battery; anything it does not cover is not verified.

## Repo map

- `app/` — routes by directory. `page.templ` → SSR page, `page.svelte` → CSR page, `layout.templ`/`layout.svelte` → layouts per level. Other files are components, not routes.
- `generated/` + `frontend/route-registry.generated.ts` — **generated, never edit**; regenerated by `make generate`.
- `internal/routing/` — discovery, normalization, validation. `internal/codegen/` — generation. `internal/httpserver/` — Fiber server, response shapes, assets. `internal/render/` — document/layout render adapters.
- `frontend/` — client runtime (no framework besides Svelte components; plain TS modules with focused ownership):
  - `entry.ts` boot; `router.ts` link interception (trust boundary); `navigation.ts` fetch; `navigation-pipeline.ts` the F12 pipeline (stale tokens, fallback); `svelte-mounter.ts` mount/unmount + instrumentation.
  - Layout system (G-phase): `layout-stack.ts` stack math, `layout-mount.ts` mounting, `layout-outlet.ts` outlets, `layout-child-swap.ts` G05 child swaps.
- `tests/browser/` — Playwright E2E (real binary). Frontend unit tests live beside their modules as `*.test.ts`.

## Critical invariants

1. **Node is build-time only.** Production = Go binary + `dist/client`. No server JS ever.
2. **Never edit generated files** (`generated/`, `frontend/route-registry.generated.ts`). Change generators, run `make generate`, expect zero drift on a clean tree.
3. **Ownership boundary (G03/G05):** everything Svelte-owned inside a mounted layout (component instance, host, marker, outlet *element*) is untouchable by navigation; the runtime owns only the outlet *interior* and page roots. Child navigation swaps the page, never the layout.
4. **Mounted vs declared:** a layout ID in a navigation envelope proves nothing. Retention decisions use tracked mount handles and DOM markers, compared as client-layout sequences (`.svelte` only) via longest-common-prefix.
5. **Trust boundary (F05):** untrusted `element.click()` is ignored by the router by design. Browser tests must use trusted input (Playwright's `page.click`) or they will silently exercise the *default* full navigation instead of the SPA path — and mislead you.
6. **Fallback policy:** any transition that would discard a mounted layout hard-navigates (teardown on exit is G07). Failed component loads must leave the current page intact.
7. **Stale-navigation safety (F11):** currency is re-checked after every await; superseded transitions are no-ops, never overwrite newer state.

## Debugging in a real browser

Append `?go-meta-debug=1` to a URL, navigate, then read
`window.__goMetaNavLog`: one entry per pipeline decision
(`retained-child-swap` / `layout-subtree-entry` / `ssr-outlet-replace` /
`hard-navigate-discard` / `stale-navigation`) with mounted/declared stacks.
This answers "which branch did the pipeline take" without guessing.

## Conventions

- Work gate-by-gate (E→F→G phases; see blueprint §5). Commit message prefix carries the gate ID (`G05: …`). Do not implement future gates early.
- Tests colocated with modules; E2E in `tests/browser/`.
- `gofmt` clean (make verify enforces), no new dependencies without need.
- `PORT` env overrides the server's default `:3000` (used by E2E).
